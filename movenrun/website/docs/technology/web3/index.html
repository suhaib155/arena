Onchain, made invisible

The plan is real ownership with none of the crypto friction. The ownership half is deployed to a test network and unused. The friction-removal half has not been started.

Why onchain at all

Ownership only means something if it is real. Territory, deeds, and $MOVE held onchain under your own keys are portable, provable, and outside any one company's control, which is what would separate a movement network from a movement app you rent. Right now MovenRun is the second kind. Zones, battles, and balances live in a Postgres database the team runs and can rewrite.

Why you never see it

Onchain has historically meant seed phrases, gas tokens, network switching, and signature prompts, and most people never climb that wall. MovenRun is designed to remove it. Here is each piece and where it actually is:

  • Embedded wallets. Designed. No provider has been selected, so no wallet is created for anyone. The interfaces exist and every provider surface fails closed.
  • Sponsored gas. Designed. There is no paymaster and no account-abstraction code in the codebase.
  • Actions, not signatures. Designed. There are no onchain actions in the app to batch.
  • One network. Base Sepolia today, chain 84532. Base mainnet is the target, and nothing has been deployed there.

Full control when you want it

Once the wallet layer exists, a crypto-native player should be able to connect an external wallet, export or take self-custody of an embedded one, and treat deeds and $MOVE like any other onchain asset. That is the intent behind the wallet-linking work already in the backend. None of it is usable, because there is nothing onchain to link to yet.

Built for Base

MovenRun is written for Base, an Ethereum Layer 2, for the low fees and fast confirmations a real-time game needs and the account-abstraction ecosystem a wallet-light onboarding depends on. The eight contracts sit on Base Sepolia, Base's test network, and have not been used.

The short version. You can play MovenRun without knowing anything about crypto. That is currently true for the least interesting reason: there is no onchain layer in the app to know about.
