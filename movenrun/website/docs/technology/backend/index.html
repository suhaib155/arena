Movement verification

Territory is only worth holding if the movement behind it was real. This is the layer that got built first, and the pipeline below runs in MovenRun's backend today.

Why it matters

An ownership economy cannot reward movement it cannot check. Verification is what keeps the map fair and the economy worth having, and it is the difference between a game of effort and a game of GPS spoofing apps.

The proof-of-movement pipeline

  1. Validate. The route is checked for physical plausibility: realistic speed, sane accuracy, continuous motion, a sane duration.
  2. Map. The path resolves to the ordered set of zones it crossed. See Territory computation.
  3. Reduce. The session is distilled into a compact, deterministic proof, which is a fingerprint of the movement rather than a stored trail.
  4. Guard. Duplicate and replayed submissions are rejected, so the same movement cannot be claimed twice.
  5. Planned: the oracle signs the proof so contracts can settle capture and rewards without trusting the client.

The oracle

The oracle is meant to be the bridge between the street and the chain, attesting with a network-held signing key that a route passed verification, with scoped and rotatable authority. The contract is deployed to Base Sepolia and holds an operator address. Nothing calls it. The backend reads from the chain and never writes to it, so verification ends at the database.

Anti-spoofing and integrity

  • Plausibility checks catch vehicles, teleports, and synthetic traces.
  • Deterministic proofs and deduplication stop replays and double claims.
  • Layered defense. Verification is expected to keep hardening as more people play, because it is the foundation everything else would stand on.

One caveat on scope. The mobile app scores its own sessions on the device and reaches the backend only for sign-in, so this pipeline is not yet in the path of a normal session. Putting it there is the next step.
